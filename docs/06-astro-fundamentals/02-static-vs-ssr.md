# Static vs SSR

## 🎓 مفهوم

سایت‌ها دو نوع هستند:

| نوع | معنی | مثال |
|---|---|---|
| **Static (SSG)** | صفحات از قبل ساخته می‌شوند | پرتفولیو، بلاگ |
| **SSR** | هر درخواست، صفحه جدید می‌سازد | فروشگاه، شبکه اجتماعی |

## 🎓 تفاوت اصلی

### Static (SSG)

```
[زمان Build]
  کد → HTML → ذخیره روی سرور
[زمان درخواست کاربر]
  کاربر → سرور → HTML آماده → کاربر
```

**مثال روزمره:** کسی کتابی را از قبل چاپ کرده، تو فقط می‌گیری.

### SSR

```
[زمان درخواست کاربر]
  کاربر → سرور → برنامه اجرا می‌شود → HTML ساخته می‌شود → کاربر
```

**مثال روزمره:** رستوران، هر سفارش را تازه می‌پزد.

## 🎓 مقایسه کامل

| معیار | Static | SSR |
|---|---|---|
| **سرعت** | ⚡ بسیار سریع | ⚠️ کندتر |
| **هزینه** | 💰 ارزان | 💰💰 گران |
| **مقیاس** | ♾️ نامحدود | محدود |
| **محتوای زنده** | ❌ نه | ✅ بله |
| **داده کاربر** | ❌ نه | ✅ بله |
| **SEO** | ✅ عالی | ✅ عالی |
| **پیچیدگی** | ساده | پیچیده |

## 🎓 SSG چطور کار می‌کند؟

### مرحله ۱: Build

وقتی دستور `npm run build` می‌زنی:

```
کد تو  →  Astro  →  HTML/CSS/JS  →  پوشه dist/
```

### مرحله ۲: Deploy

پوشه `dist/` را روی سرور می‌گذاری.

### مرحله ۳: کاربر

کاربر وارد سایت می‌شود:

```
GET /  →  سرور  →  index.html (آماده)  →  کاربر
```

**زمان پاسخ:** میلی‌ثانیه.

## 🎓 در Astro، ما Static هستیم

### چرا؟

| دلیل | توضیح |
|---|---|
| محتوای ما ثابت است | پرتفولیو، هر چند وقت یک بار عوض می‌شود |
| سرعت فوق‌العاده | لود زیر ۱ ثانیه |
| Deploy ساده | فقط فایل‌های استاتیک |
| هزینه کم | حتی Liara رایگان کافی است |
| امنیت بالا | بدون دیتابیس، بدون Backend |

### محتوای ما کجا ذخیره می‌شود؟

**قبل از Build:** در `master_data.json`.

**بعد از Build:** در HTML نهایی.

**مثال:**

`master_data.json`:

```json
{
  "projects": [
    {"title": "پروژه A", "area": 5000}
  ]
}
```

`index.html` بعد از Build:

```html
<h1>پروژه A</h1>
<p>مساحت: 5000 مترمربع</p>
```

**همه چیز در HTML پخته شده.**

## 🎓 مزیت Static برای ما

### ۱. سرعت

سایت ما روی Liara، در ایران، زیر ۱ ثانیه لود می‌شود.

**چرا؟** HTML آماده است. هیچ پردازشی روی سرور نیست.

### ۲. SEO

Google HTML خالص را دوست دارد.

**نتیجه:** سایت در نتایج جستجو بالا می‌آید.

### ۳. هزینه

Liara پلن رایگان برای سایت استاتیک کافی است.

**چرا؟** سرور فقط فایل می‌فرستد. هیچ پردازشی نیست.

### ۴. امنیت

بدون دیتابیس، بدون Backend، بدون API. هیچ راهی برای هک نیست.

### ۵. Git-Friendly

پوشه `dist/` را می‌توانی در Git نگه‌داری.

## 🎓 چه زمانی SSR لازم است؟

اگر سایت تو این ویژگی‌ها را داشت:

| ویژگی | چرا SSR لازم است |
|---|---|
| ورود کاربر | باید Session مدیریت شود |
| پنل کاربری | داده شخصی نمایش داده شود |
| فروشگاه | سبد خرید زنده |
| کامنت زنده | هر لحظه بروز شود |
| داده Real-time | تغییرات فوری |

**ما هیچ‌کدام را نداریم.**

## 🎓 Astro هر دو را پشتیبانی می‌کند

Astro در حالت **Static** پیش‌فرض است. اما اگر روزی خواستی، می‌توانی SSR فعال کنی:

```javascript
// astro.config.mjs
export default defineConfig({
  output: 'server',  // SSR
});
```

**اما این کار نیاز به Adapter دارد** (Node، Vercel، Netlify و ...). Liara هم Adapter دارد.

**فعلاً ما Static می‌مانیم.**

## 🎓 مفهوم: Build Time vs Request Time

| اصطلاح | معنی |
|---|---|
| **Build Time** | وقتی `npm run build` می‌زنی |
| **Request Time** | وقتی کاربر درخواست می‌فرستد |

**Static:** کار در Build Time.

**SSR:** کار در Request Time.

## 🎓 مثال واقعی از پروژه ما

### در حالت Static (فعلی)

```
۱. کد را می‌نویسی
۲. master_data.json آماده است
۳. npm run build
۴. Astro همه صفحات را می‌سازد:
   - index.html
   - portfolio/index.html
   - portfolio/media-building-phase1/index.html
   - about/index.html
   - contact/index.html
۵. پوشه dist/ روی Liara
۶. کاربر → فایل‌ها را می‌گیرد → تمام
```

**زمان پاسخ: ۵۰ میلی‌ثانیه.**

### اگر SSR بود

```
۱. کاربر درخواست می‌فرستد
۲. سرور Node.js روشن می‌شود
۳. master_data.json را می‌خواند
۴. صفحه را می‌سازد
۵. HTML را می‌فرستد
۶. تازه بعد از این، صفحه می‌رسد
```

**زمان پاسخ: ۳۰۰+ میلی‌ثانیه.**

**۷ برابر کندتر.**

| ساخت صفحه | در Build | در Request |

| هزینه | ارزان | گران |
| محتوای زنده | ❌ | ✅ |
| امنیت | بالا | متوسط |
| مناسب ما | ✅ | ❌ |
