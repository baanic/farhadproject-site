# Git چیست؟

## 🎓 مفهوم

**Git** یک **سیستم کنترل نسخه** (Version Control System) است.

### تعریف ساده

ابزاری که **تاریخچه تغییرات** فایل‌هایت را نگه می‌دارد. هر لحظه می‌توانی ببینی چه تغییری داده‌ای، چه کسی داده، و چه زمانی.

### قیاس روزمره

تصور کن دفتر خاطراتی داری:
- هر روز یک صفحه می‌نویسی.
- صفحات قبلی پاک نمی‌شوند.
- می‌توانی به هر صفحه قبلی برگردی.

**Git همین است، برای کد.**

## 🎓 چرا Git لازم است؟

### مشکل ۱: نسخه‌های تکراری

بدون Git، معمولاً این کار را می‌کنی:

```
thesis.docx
thesis-final.docx
thesis-final-v2.docx
thesis-final-v2-corrected.docx
thesis-final-v2-corrected-really.docx
thesis-final-v2-corrected-really-this-is-it.docx
```

**آشنا به نظر می‌رسد؟** این روش:
- گیج‌کننده است.
- فضای دیسک را هدر می‌دهد.
- تشخیص تفاوت‌ها سخت است.

با Git:

```
thesis.docx   ← یک فایل، اما با ۶ نسخه در تاریخچه
```

### مشکل ۲: برگشت به نسخه قبلی

بدون Git:
- فایل را اشتباهاً خراب می‌کنی.
- Save می‌کنی.
- نمی‌توانی برگردی.

با Git:
- فایل را خراب می‌کنی.
- `git checkout HEAD~1 thesis.docx` می‌زنی.
- برمی‌گردی به نسخه قبل.

### مشکل ۳: همکاری چند نفره

بدون Git:
- نفر A فایل را ویرایش می‌کند.
- نفر B همزمان ویرایش می‌کند.
- تغییرات یکی روی دیگری بازنویسی می‌شود.

با Git:
- Git تغییرات هر دو را ادغام می‌کند.
- اگر تعارض بود، هشدار می‌دهد.

## 🎓 تاریخچه Git

### سال ۲۰۰۵

**Linus Torvalds** (سازنده لینوکس) داشت روی هسته Linux کار می‌کرد. ابزار قبلی، BitKeeper، رایگان نبود. Linus تصمیم گرفت **Git** را بسازد.

**هدفش:**
- سریع باشد.
- توزیع‌شده باشد.
- امن باشد.

**نتیجه:** Git در کمتر از ۲ هفته نوشته شد. حالا **استاندارد صنعت** است.

## 🎓 مفاهیم کلیدی Git

### Repository (مخزن)

یک پوشه که Git آن را **رصد می‌کند**. شامل:
- تمام فایل‌های پروژه.
- پوشه مخفی `.git` که تاریخچه در آن است.

### Commit (ثبت)

یک **عکس فوری** از پروژه در لحظه‌ای خاص.

هر Commit شامل:
- تغییرات فایل‌ها.
- نام و ایمیل نویسنده.
- تاریخ و زمان.
- پیام توضیحی.
- یک **هش** (Hash) یکتا برای شناسایی.

### Branch (شاخه)

یک **خط موازی توسعه**. شاخه اصلی معمولاً `main` است.

**چرا Branch؟**
- برای ساخت ویژگی جدید بدون خراب کردن شاخه اصلی.
- برای تست ایده‌های جدید.
- برای همکاری تیمی.

### Merge (ادغام)

ترکیب یک Branch با Branch دیگر.

## 🎓 Git توزیع‌شده (Distributed)

Git **توزیع‌شده** است. یعنی:

- هر کاربر، **کل تاریخچه** را روی کامپیوتر خودش دارد.
- لازم نیست همیشه به سرور وصل باشی.
- می‌توانی آفلاین Commit بزنی.
- سرور (GitHub) فقط یک نقطه هماهنگی است.

### مقایسه با Centralized

| متمرکز (SVN، CVS) | توزیع‌شده (Git، Mercurial) |
|---|---|
| یک سرور مرکزی | هر کاربر یک نسخه کامل |
| بدون شبکه نمی‌توانی Commit بزنی | آفلاین هم کار می‌کند |
| سرور خراب شود، تاریخچه از دست می‌رود | همه نسخه کامل دارند |

## 🎓 Git در پروژه ما

در این پروژه، ما Git را در پوشه `farhadproject` راه‌اندازی کردیم:

```bash
cd ~/Documents/Projects/farhadproject
git init
```

از آن لحظه، هر تغییر در Git ثبت شد. الان بیش از ۲۰ Commit داریم که نشان‌دهنده سیر پروژه است.

**نگاهی به تاریخچه:**

```bash
git log --oneline
```

خروجی نمونه:

```
ed542ed Add dev environment documentation (6 files)
78bd3ff Add terminal basics documentation (5 files)
ef56f61 Add documentation index and introduction
...
fac6023 Initial commit: project structure and README
```

هر خط، یک Commit است. اولین خط (بالاترین) جدیدترین است.

## 💡 چرا Git برای ما حیاتی است؟

### ۱. اگر خرابکاری کنی، برمی‌گردی

مثلاً فرض کن فایل `index.astro` را اشتباهاً پاک کردی:

```bash
git checkout HEAD index.astro
```

فایل بازگردانده می‌شود.

### ۲. تاریخچه یادگیری

Commit‌های این پروژه، تاریخچه یادگیری تو هستند. کارفرمای آینده می‌بیند چطور از صفر شروع کردی.

### ۳. Deploy خودکار

Liara می‌تواند به GitHub وصل شود و هر بار که Push می‌کنی، خودش سایت را Deploy کند.

## 🎁 خلاصه

| مفهوم | توضیح |
|---|---|
| Git | سیستم کنترل نسخه |
| Repository | پوشه تحت رصد |
| Commit | عکس فوری از پروژه |
| Branch | خط موازی توسعه |
| Merge | ادغام Branch‌ها |
| توزیع‌شده | هر کاربر نسخه کامل دارد |
