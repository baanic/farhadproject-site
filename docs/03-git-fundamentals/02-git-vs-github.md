# Git vs GitHub

## 🎓 مفهوم

این دو کلمه، بسیار شبیه‌اند و بسیاری آن‌ها را یکی می‌گیرند. اما **دو چیز کاملاً متفاوت** هستند.

## 🎓 تفاوت اصلی

| Git | GitHub |
|---|---|
| **ابزار** | **سرویس** |
| روی کامپیوتر نصب می‌شود | آنلاین است |
| خط فرمان | وب‌سایت |
| توزیع‌شده | متمرکز |
| رایگان و Open Source | رایگان با پلن‌های حرفه‌ای |
| سال ۲۰۰۵ ساخته شد | سال ۲۰۰۸ ساخته شد |

### قیاس ساده

| Git | GitHub |
|---|---|
| مثل **دفتر خاطرات** | مثل **وبلاگ خاطرات** |
| خصوصی، روی کامپیوتر خودت | عمومی، روی اینترنت |
| برای تو | برای اشتراک با دیگران |

## 🎓 Git بدون GitHub

می‌توانی Git داشته باشی و از آن استفاده کنی، **بدون GitHub**.

**سناریو:** یک پروژه شخصی روی لپ‌تاپ، می‌خواهی تاریخچه داشته باشی.

```bash
cd ~/Documents/Projects/my-project
git init
# کار کن، Commit بزن
# همه چیز روی کامپیوتر خودت
```

**Git کار می‌کند، اما:**
- فقط روی کامپیوتر خودت است.
- اگر لپ‌تاپ خراب شود، همه چیز از دست می‌رود.

## 🎓 GitHub بدون Git

**غیرممکن است.** GitHub روی Git ساخته شده. برای استفاده از GitHub، باید Git را بفهمی.

## 🎓 چرا GitHub محبوب است؟

### ۱. سرویس رایگان

مخزن عمومی نامحدود، رایگان.

### ۲. اجتماعی

می‌توانی پروژه‌های دیگران را ببینی، Fork کنی، Pull Request بدهی.

### ۳. تعامل با ابزارها

- Vercel، Netlify، Liara: Deploy خودکار از GitHub.
- CI/CD: تست و Build خودکار.

### ۴. پورتفولیو

کارفرمایان، پروفایل GitHub را بررسی می‌کنند.

## 🎓 گزینه‌های جایگزین GitHub

GitHub تنها سرویس Git نیست:

| سرویس | مزیت | عیب |
|---|---|---|
| **GitHub** | بزرگ‌ترین، استاندارد | مایکروسافت مالکش است |
| **GitLab** | Open Source، CI/CD داخلی | کمی پیچیده‌تر |
| **Bitbucket** | یکپارچه با Atlassian | کمتر محبوب |
| **Codeberg** | Open Source، غیرانتفاعی | کوچک‌تر |
| **Gitea** | خود میزبانی | نیاز به سرور |

**ما GitHub انتخاب کردیم** چون:
- استاندارد صنعت است.
- با Liara یکپارچه می‌شود.
- پروفایل عمومی برای پرتفولیو.

## 🎓 مفاهیم مشترک

### Repository (Repo)

- **در Git:** پوشه‌ای با `.git`.
- **در GitHub:** یک صفحه وب که مخزن آنلاین را نشان می‌دهد.

### Clone

گرفتن یک کپی از مخزن GitHub به کامپیوتر خودت:

```bash
git clone https://github.com/user/repo.git
```

### Push

فرستادن Commit‌های محلی به GitHub:

```bash
git push
```

### Pull

گرفتن تغییرات از GitHub:

```bash
git pull
```

## 🎓 در پروژه ما

### Git (محلی)

```bash
cd ~/Documents/Projects/farhadproject
git log --oneline
```

تاریخچه محلی.

### GitHub (آنلاین)

آدرس مخزن:
```
https://github.com/baanic/farhadproject-site
```

هر Commit که Push می‌کنی، روی GitHub قابل مشاهده است.

### ارتباط این دو

```bash
git remote -v
```

خروجی:

```
origin  https://github.com/baanic/farhadproject-site.git (fetch)
origin  https://github.com/baanic/farhadproject-site.git (push)
```

کلمه `origin` نام پیش‌فرض مخزن ریموت است.

## 💡 نکته مهم

**بسیاری از مبتدی‌ها فکر می‌کنند Git = GitHub.** این اشتباه، باعث سردرگمی می‌شود.

**قانون طلایی:**
- **Git** = ابزار.
- **GitHub** = سرویس.

اگر یک روز GitHub را ترک کنی، Git همچنان کار می‌کند. می‌توانی به GitLab یا Bitbucket بروی.

| همکاری | محلی | تیمی |
| توزیع | توزیع‌شده | متمرکز |
