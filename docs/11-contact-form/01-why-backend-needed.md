# چرا Backend لازم است؟

## 🎓 مفهوم

**Backend** = بخشی از سایت که در **سرور** اجرا می‌شود.

## 🎓 Frontend vs Backend

| Frontend | Backend |
|---|---|
| در مرورگر کاربر | در سرور |
| HTML/CSS/JS | Node.js/Python/PHP |
| می‌بیند | پردازش می‌کند |
| سریع | کندتر |

## 🎓 فرم تماس چه می‌خواهد؟

1. **گرفتن داده** از کاربر.
2. **ذخیره یا فرستادن** داده به یک جا.
3. **پاسخ دادن** به کاربر.

## 🎓 سایت Static چه کم دارد؟

**سایت Static:**
- فقط HTML/CSS/JS.
- فقط مرورگر.
- **هیچ Backend ندارد.**

**پس:**
- داده را کجا ذخیره کنی؟
- ایمیل را چطور بفرستی؟
- پاسخ را چطور بدهی؟

## 🎓 سه راه‌حل

### راه ۱: سرور Node.js بساز

```
کاربر → فرم → سرور شما (Node.js) → ایمیل به شما
```

**مشکل:**
- نیاز به سرور.
- هزینه.
- پیچیدگی.
- امنیت.

### راه ۲: PHP روی cPanel

```
کاربر → فرم → PHP Script → ایمیل
```

**مشکل:**
- ما از Astro Static استفاده می‌کنیم.
- PHP با Astro سازگار نیست.
- محدودیت‌های هاست.

### راه ۳: سرویس خارجی (ما)

```
کاربر → فرم → Web3Forms (سرور خارجی) → ایمیل شما
```

**مزیت:**
- بدون Backend.
- بدون هزینه.
- امن.

**عیب:**
- وابسته به سرویس.
- محدودیت پیام.

## 🎓 مقایسه

| راه‌حل | هزینه | پیچیدگی | مناسب ما |
|---|---|---|---|
| Node.js Server | $$$ | بالا | ❌ |
| PHP Script | $ | متوسط | ❌ |
| Web3Forms | رایگان | کم | ✅ |

## 🎓 چطور کار می‌کند؟

```
[مرورگر کاربر]
    │
    │ ۱. کاربر فرم را پر می‌کند
    │
    ├──► JavaScript درخواست POST می‌فرستد
    │
    ▼
[سرور Web3Forms]
    │
    │ ۲. Web3Forms ایمیل می‌سازد
    │
    ├──► ارسال به ایمیل شما
    │
    ▼
[ایمیل شما]
    │
    │ ۳. پاسخ موفقیت به مرورگر
    │
    ▼
[مرورگر کاربر]
```

## 🎓 مفهوم: API

**API** = **A**pplication **P**rogramming **I**nterface.

رابط بین دو برنامه. به زبان ساده: «راهی که یک برنامه با برنامه دیگر صحبت می‌کند.»

**Web3Forms API:**

```
POST https://api.web3forms.com/submit
{
  "access_key": "your-key",
  "name": "فرهاد",
  "email": "user@example.com",
  "message": "سلام"
}
```

## 🎓 مفهوم: HTTP Request

**HTTP Request** = درخواست از مرورگر به سرور.

### متدها

| متد | کاربرد |
|---|---|
| **GET** | خواندن |
| **POST** | فرستادن |
| **PUT** | بروزرسانی |
| **DELETE** | حذف |

**ما از POST استفاده می‌کنیم.**

### ساختار

```
POST https://api.web3forms.com/submit
Headers:
  Content-Type: application/json
Body:
  { "name": "فرهاد", ... }
```

## 🎓 چرا این روش امن است؟

1. **Access Key** فقط برای ایمیل شما کار می‌کند.
2. **HTTPS** داده را رمزنگاری می‌کند.
3. **Botcheck** جلوی ربات‌های اسپم را می‌گیرد.
4. **Rate Limiting** جلوی حملات را می‌گیرد.

## 🎓 محدودیت‌ها

| محدودیت | مقدار |
|---|---|
| پیام در ماه (رایگان) | ۲۵۰ |
| حجم هر پیام | محدود |
| فایل پیوست | در پلن حرفه‌ای |

**برای ما کافی است.**

## 🎓 چرا انتخاب کردیم؟

- **پروژه ما Static است.**
- **Backend نمی‌خواهیم.**
- **هزینه نمی‌خواهیم.**
- **پیام‌ها کم هستند.**
- **Web3Forms ساده است.**

## 🎓 نتیجه

**سایت Static + Web3Forms = فرم تماس کارآمد بدون Backend.**

## 🎁 خلاصه

| مفهوم | توضیح |
|---|---|
| Backend | سرور |
| Static | بدون سرور |
| API | رابط برنامه |
| HTTP | پروتکل |
| POST | درخواست ارسال |
| Web3Forms | سرویس واسط |
