# ساخت مخزن در GitHub

## 🎓 مفهوم

**Repository (مخزن)** در GitHub، یک **پروژه آنلاین** است.

هر پروژه‌ای که می‌خواهی در GitHub داشته باشی، اول باید یک Repository بسازی.

## 🎓 دو نوع مخزن

| نوع | کاربرد | هزینه |
|---|---|---|
| **Public** (عمومی) | همه می‌بینند | رایگان و نامحدود |
| **Private** (خصوصی) | فقط تو و افراد مجاز | رایگان تا ۳ نفر همکار |

## 🛠 گام ۱: رفتن به صفحه ساخت

آدرس: [github.com/new](https://github.com/new)

یا:

1. وارد [github.com](https://github.com) شو.
2. روی آیکون **+** (بالا راست).
3. **New repository**.

## 🛠 گام ۲: پر کردن فرم

### ۱. Repository name

نام **یکتا** برای پروژه. **قواعد:**

- فقط حروف کوچک: `a-z`
- اعداد: `0-9`
- خط تیره: `-`
- زیرخط: `_`
- نقطه: `.`

**پیشنهاد نام‌گذاری:**

| قالب | مثال |
|---|---|
| `kebab-case` | `farhadproject-site` ✅ |
| `snake_case` | `farhadproject_site` |
| `CamelCase` | ❌ (استاندارد نیست) |

**نام ما:** `farhadproject-site`

### ۲. Description (اختیاری ولی توصیه‌شده)

توضیح کوتاه درباره پروژه. یک جمله.

**مثال:**

```
Portfolio website for Farhad — Technical Office, Project Controls, QS & Acoustics
```

**چرا؟**
- در نتایج جستجوی GitHub نمایش داده می‌شود.
- به دیگران می‌گوید پروژه چیست.
- **در Google هم دیده می‌شود** (به SEO کمک می‌کند).

### ۳. Visibility

| گزینه | توضیح |
|---|---|
| **Public** | هر کسی می‌بیند. مناسب پرتفولیو |
| **Private** | فقط تو. مناسب پروژه‌های حساس |

**انتخاب ما:** **Public**

چرا؟
- پرتفولیو است و می‌خواهیم کارفرمای آینده ببیند.
- GitHub Actions در پلن رایگان برای Public محدودیت کمتری دارد.
- نمونه کار حرفه‌ای است.

### ۴. Initialize this repository

**این بخش، تله‌ی مهمی دارد.**

سه گزینه می‌بینی:

| گزینه | توصیه |
|---|---|
| **Add a README file** | ❌ **تیک نزن** |
| **Add .gitignore** | ❌ **تیک نزن** |
| **Choose a license** | ⚠️ در این مرحله نه |

**چرا؟**

ما می‌خواهیم مخزن را **از صفر** بسازیم و خودمان اولین Commit را بزنیم.

اگر GitHub این فایل‌ها را بسازد:
- مخزن از قبل یک Commit دارد.
- موقع `git init` محلی، تناقض ایجاد می‌شود.
- مجبور می‌شوی `git pull` بزنی و Merge کنی.

**پس همه را خالی بگذار.**

## 🛠 گام ۳: ساخت

1. تنظیمات را دوباره چک کن.
2. **Create repository** (پایین صفحه).

## 🎓 چه اتفاقی می‌افتد؟

GitHub یک صفحه به تو نشان می‌دهد:

> **Quick setup — if you've done this kind of thing before**

این صفحه راهنمای اتصال مخزن خالی به مخزن محلی است. **ما دقیقاً همین کار را در گام بعدی انجام می‌دهیم.**

**اطلاعات مهم که در این صفحه است:**

**URL مخزن:**

```
https://github.com/baanic/farhadproject-site.git
```

**این URL را نگه‌دار.** در گام بعدی به آن نیاز داریم.

## 🎓 آدرس‌های مختلف مخزن

هر مخزن، چند آدرس دارد:

| URL | پروتکل | کاربرد |
|---|---|---|
| `https://github.com/user/repo.git` | HTTPS | توصیه‌شده برای مبتدی |
| `git@github.com:user/repo.git` | SSH | حرفه‌ای‌ها |
| `gh repo clone user/repo` | GitHub CLI | با `gh` |

**ما از HTTPS استفاده می‌کنیم.**

## 🎓 مخزن‌های Private

اگر بعداً بخواهی مخزن را Public کنی یا برعکس:

1. مخزن → **Settings**.
2. پایین صفحه → **Danger Zone**.
3. **Change visibility**.

**نکته:** Change visibility ممکن است بعضی چیزها را از دست بدهد (مثل Forkها، Stars). با احتیاط.

## 🎓 بعد از ساخت، چه ببینی؟

صفحه مخزن GitHub خالی است. یک متن می‌بینی:

> **This repository is empty.**

و راهنمای اتصال.

**این طبیعی است.** مخزن تازه ساخته شده و هنوز هیچ کدی در آن نیست. در گام بعدی، اولین کد را Push می‌کنیم.

## 🎓 در پروژه ما

ما همین مراحل را انجام دادیم:

| تنظیم | مقدار |
|---|---|
| Repository name | `farhadproject-site` |
| Description | Portfolio website for Farhad |
| Visibility | Public |
| Initialize | هیچ‌کدام |
| URL | `https://github.com/baanic/farhadproject-site.git` |

## 🛑 عیب‌یابی

### مشکل ۱: نام مخزن قبلاً استفاده شده

**علت:** نام‌های GitHub **جهانی** هستند. یعنی هر کاربری در GitHub، نام یکتا دارد.

**راه‌حل:**
- نام دیگری انتخاب کن.
- مثلاً `farhadproject-website` یا `farhadportfolio`.

### مشکل ۲: می‌خواهم مخزن را پاک کنم

1. مخزن → **Settings**.
2. پایین → **Danger Zone**.
3. **Delete this repository**.
4. نام مخزن را تایپ کن (تأیید).

⚠️ **هشدار:** این کار **بازگشت‌ناپذیر** است. تمام تاریخچه از دست می‌رود.

### مشکل ۳: تیک README را زدم

**نگران نباش.** می‌توانی محلی مخزن را Clone کنی و کار کنی. اما چون ما محلی مخزن داریم، به‌جای `git init` باید `git pull` بزنی.
